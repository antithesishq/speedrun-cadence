## Deployment
3 cadence nodes (all four services each: frontend, history, matching, worker), ringpop membership, 8 history shards (variant -b: 16), Postgres default store + DB visibility, 3 client containers (Go client + worker, stateful-clients pattern, JSON-RPC over unix socket), 1 driver (fault-excluded). Supervisor entrypoint restarts cadence-server after a crash exit (like Kubernetes restartPolicy Always) and reports Go panics as an assertion. Faults: Antithesis high_availability (container kill/stop/pause, network partitions and degradation, CPU throttling, clock jitter) on everything except the driver; Postgres included.

Tuning (config-template/dynamicconfig.yaml; production default in parentheses):
- history.cacheMaxSize 20 (512) — reload mutable state from DB often (variant -b uses default)
- history.cacheTTL 30s (1h) (variant -b uses default)
- matching.numTasklist{Write,Read}Partitions 3 (1) (variant -b: 1)
- matching.idleTasklistCheckInterval 20s, matching.updateAckInterval 5s, history.shardUpdateMinInterval 1s, history.{timer,transfer}ProcessorUpdateAckInterval 5s — more frequent persistence/ownership churn
- frontend/history shutdownDrainDuration 0s — stops behave like crashes
- history.decisionHeartbeatTimeout 1m (30m) — added after the decision-heartbeat finding so one stuck workflow can't mask others; the finding was found with the default
- system.minRetentionDays 0
Postgres: idle_in_transaction_session_timeout=30s, tcp keepalives 10/5/3 (production-like; added after orphaned locks from killed processes held shard rows for hours — rca/shard-unavailable-after-faults.md).

## Workflows / checks
See antithesis/README.md. Workflow types: counter (signals add/finish, query, continue-as-new, cancel, reset target), chain (activities with retries/heartbeats/parallel/local), timer, parent (children), race (timers racing long local activities → decision heartbeats; 4 s decision timeout). Rules: start / signal-with-start, signal, finish, query, cancel, terminate, reset, duplicate start of open ID, reuse of closed ID with reuse policy, result read + history check, describe closed, eventually.
